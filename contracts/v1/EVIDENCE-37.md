# Issue #37 — integrated V1 release qualification

## Decision

This is a gap report, not a release pass. The repository has broad automated coverage across the shared review services, CLI, native adapter and bounded renderer spike, but the evidence does not establish that all eleven V1 acceptance criteria work together as installed workflows. Criteria 1–4 remain partial; criterion 5 is satisfied as a reporting artifact. Do not mark the complete V1 workflow qualified from the current evidence.

The latest integrated `CARGO_BUILD_JOBS=2 ./scripts/validate desktop` run passed after the review-cleanup refactor at integration revision `d1a0627`; its full output is [VALIDATE-REVIEW-FIX-RETRY.log](VALIDATE-REVIEW-FIX-RETRY.log). The first run is preserved in [VALIDATE-REVIEW-FIX.log](VALIDATE-REVIEW-FIX.log); no cause was established, so it remains recorded as an intermittent failure. This is a code/build/test result: it opens no GUI and proves neither hosted CI nor user interaction. ## Integrated cross-cutting checks

- **Concurrency and migration:** `tests/preparation.rs` covers simultaneous first-open migration, lock contention and retained preparation data. `tests/manual_drafts.rs` covers stale concurrent draft writes. This does not include a native preference write racing cleanup while a review-content write is in flight.
- **Head and permissions:** controlled `gh` tests in `tests/manual_review.rs`, `tests/discussion_drafts.rs`, and `tests/discussion_publication.rs` reject changed heads or lost permissions before writes. No live permission/head race was attempted.
- **Unknown send and restart:** controlled publisher tests persist unknown state and prevent blind retries. No remote reconciliation run was performed.
- **Migration/cache:** [#34 evidence](EVIDENCE-34.md) proves transactional migrations and per-preparation discussion-observation count bounds. Global preparation/context eviction, total database byte budgets, forced Git-object eviction and the full repeated prepare/import/follow-up/publication/restart cycle remain unqualified.
- **Keyboard, focus, resize and themes:** code and focused spike tests cover hit mapping, pane geometry, keyboard selection, theme state and narrow-window layout; [renderer evidence](../spikes/native-sequence/EVIDENCE.md) includes actual user feedback for the optimized diagnostic spike. This is not an app-wide keyboard/focus/theme/resize trial across Overview, Changes, Findings and Finish Review. The #32 Findings visual acceptance covers composition only.
- **Untrusted content:** `spikes/native-sequence/tests/manual_review.rs::full_markdown_becomes_safe_readable_blocks_with_inert_html_and_links` verifies inert HTML and unsafe-link rendering. `tests/cli.rs` and `tests/contract.rs` verify malformed/unknown inputs fail with structured errors. No hostile repository content has been exercised through every installed UI surface.
- **Platform/performance:** [#36 evidence](EVIDENCE-36.md) records the supported Wayland host and public `github.com` capability boundary, prior sequence-renderer CPU comparison and real feedback, and the attempted cold build that stopped before running. It explicitly leaves real large-PR behavior, end-to-end storage/memory limits, inactive-resource behavior, X11, other distributions and Enterprise unverified.
- **Installation:** [#35 evidence](EVIDENCE-35.md) records successful local-prefix installation, out-of-checkout CLI invocation and a native launcher start. Desktop-menu activation and a complete installed V1 workflow were not exercised.
