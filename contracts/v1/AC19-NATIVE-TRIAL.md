# Issue #19 native replacement trial — 2026-11-07

## Purpose and boundary

Qualify exact source-span capture, editable replacement text, keyboard input case, local save/resume, focus/theme presentation, and the no-write boundary for the native code-replacement editor. The GUI used an isolated copy of the prepared self-PR #38 state and a temporary XDG state directory. It did not modify the repository checkout or make a GitHub write.

## Reproduction and result

- Before the fix, selecting Head line 2 while the source pane showed lines 1–80 and choosing **Draft replacement** produced `REPLACEMENT_SOURCE_CHANGED` on save. The failed target-only capture is [preserved](../../spikes/native-sequence/evidence/issue-37-ac19-replacement-span-failure-2026-11-07.png).
- Root cause: the UI passed the complete loaded source excerpt to the replacement draft instead of slicing the selected `SourceRef` range. `source_excerpt_for_anchor` now verifies path, revision, and inclusive line bounds, then preserves the selected bytes (including CRLF and a missing final newline). If the requested span is not in the loaded excerpt, the UI requests a reload.
- Regression tests cover selecting one line from a broader CRLF excerpt and rejecting a mismatched revision. The focused tests passed; the full desktop validation passed after the source-span and input changes. Raw output is [here](VALIDATE-37-SHIFTED-EDITOR-INPUT-2026-11-07.log). An earlier full desktop pass after only the span fix is [also preserved](VALIDATE-37-REPLACEMENT-SPAN-2026-11-07.log).
- During a native input pass, typing `API_KEY := CamelCase` through the replacement editor displayed and saved lowercase. GPUI exposes the produced character separately from the physical key name; editor handlers had inserted the latter. All six manual draft editors, the review summary, PR search, and changed-file filter now use the shared `typed_text` helper, which preserves the produced character and rejects control/platform shortcuts.
- The fixed installed app was launched on Hyprland workspace 2 at PID `3920543`, window origin `(-1912, 668)`, size `1904×1020`. In a copied review database, the existing exact Head line 2 replacement was resumed and edited with `wtype`; the visible original remained `use super::diagram::SequenceDiagram;` and the proposed replacement was `API_KEY := CamelCase`. Target-only captures show the exact-line editor [before save](../../spikes/native-sequence/evidence/issue-37-ac19-uppercase-input-exact-anchor-2026-11-07.png), the saved replacement in Finish Review [with no event selected and the explicit confirm boundary](../../spikes/native-sequence/evidence/issue-37-ac19-uppercase-input-finish-review-2026-11-07.png), and the restored editor [after restarting the app](../../spikes/native-sequence/evidence/issue-37-ac19-uppercase-input-restarted-2026-11-07.png).
- The isolated CLI readback is [here](AC19-UPPERCASE-REPLACEMENT-LIST.json): it reports Head line 2–2, the exact original source line, `API_KEY := CamelCase`, and replacement revision 2. The same prepared state was reopened after the GUI restart; the saved editor and text remained available.
- The `.git/index` and `spikes/native-sequence/src/product.rs` SHA-256 values matched before and after the GUI trial; both files are recorded [before](AC19-SOURCE-INDEX-BEFORE.sha256) and [after](AC19-SOURCE-INDEX-AFTER.sha256). The checkout was not changed by the review workflow. Finish Review showed the replacement as a local suggestion; no review event was selected and confirmation was not activated.
- A separate input-only pass initially selected lines 1–80, saved the typed text, verified the case, then explicitly discarded that broad-range artifact. It is not used as exact-anchor evidence. A failed attempt to install into `/tmp` due to a full tmpfs is recorded in [the install log](INSTALL-37-AC19-REPLACEMENT-2026-11-07.log); the retry and final build succeeded under `/home/kedarmd/tmp` ([retry log](INSTALL-37-AC19-REPLACEMENT-RETRY-2026-11-07.log)).
