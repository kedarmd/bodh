# Issue #13 preparation evidence

This slice adds a shared headless prepare service and SQLite preparation store. It is deliberately limited to an ordinary GitHub.com pull request whose authoritative base and head commits are already present in the selected non-shallow checkout. The adapter reads PR metadata through installed authenticated `gh`, pins the supplied SHAs, derives a unique merge base and indexes the immutable commit diff. It never checks out a ref or reads dirty source files. Missing objects, shallow history, unsupported/ambiguous remotes and gh auth/network failures stop preparation explicitly.

SQLite is provided by `rusqlite 0.38.0` with its `bundled` feature and bundled SQLite C source. Migrations use SQLite `user_version=1`, foreign keys and WAL with a bounded busy wait. The acquisition work occurs before the short final persistence transaction. Comparison identity and per-invocation preparation bindings are separate; title and original description are snapshotted per preparation so later edits do not overwrite earlier snapshots.

`cargo test --locked --test preparation` uses real temporary Git and SQLite databases plus controlled executables for `gh`. It verifies a normal PR, pinned changed-file and patch inspection, actual CLI prepare/source-inspect envelopes, dirty/staged/index/HEAD/branch preservation, repeat preparation IDs, metadata snapshots and reopening persisted preparations. Missing-gh, HTTP 401 and cancellation/deadline outcomes are checked against the same checkout snapshots. The test seam accepts an explicit `gh` executable path; production resolves `gh` from PATH. No live GitHub call or remote mutation is part of this evidence.

The full `CARGO_BUILD_JOBS=2 ./scripts/validate` core runner passed on Linux x86_64, Rust/Cargo 1.99.0 after the CLI source-inspection and failure-matrix tests were added. This includes runner Python tests, headless PR capability harness tests, formatting, check, Clippy, all contract/evidence/findings/preparation integration tests, and the native-sequence spike tests. No GUI or live remote trial was run.

Current limits: acquisition does not fetch absent pinned objects; does not support shallow history, GitHub Enterprise, fork-specific ref retrieval, discussions or previous-result import. File pages are capped at 100 entries and patch pages at 64 KiB; a single patch is bounded by the shared Git output limit. `gh` runs without a shell in a process group, with bounded stdout/stderr and the shared operation deadline/cancellation. These limitations are not claims of complete product acquisition and are carried forward for integration follow-up.
