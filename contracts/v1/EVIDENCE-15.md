# Issue #15 discussion acquisition evidence

`inspect --kind discussions` now performs read-only GitHub GraphQL acquisition from the stored preparation identity. It paginates the review-thread connection first, then paginates every acquired thread's comments connection independently. Each successful page is committed in its own short SQLite transaction before the next request; later transport, permission, timeout, malformed-cursor, repeated-cursor, duplicate/null-node, count-change, or size-limit failures preserve those earlier pages and identify the affected connection and cause.

The additive SQLite schema uses its own `discussion_schema_migrations` version table (version 1) alongside the preparation database's existing `PRAGMA user_version=1`. This lets discussions upgrade an existing issue #13 database without rewriting the preparation schema version. Page rows reference the preparation and observation with foreign keys; WAL is enabled. Acquisition never runs while a database write transaction is open. Restart tests reopen the original preparation and the complete/partial discussion observations.

The compact prepare/manifest summaries expose expected/fetched thread and comment counts, availability, completeness, the first affected connection/cause, count-change status, and `moving_non_atomic` consistency. Unknown totals remain `null`. Inspection retains each thread's GraphQL node ID, comment/reply GraphQL IDs, exact decimal database IDs, `replyTo` relationship, author/association, body/timestamps, paths, current/original line ranges, diff sides, resolution/outdated state, and viewer permissions. The current GraphQL schema exposes `diffSide` and `startDiffSide` but no original-side fields; the result sets original-side values to null and reports `original_side_availability=not_exposed_by_graphql` instead of inferring them.

Controlled `gh` fixtures cover multiple outer and nested pages, an empty discussion with unknown total, restart and preparation-schema migration, comments and thread metadata, GraphQL partial permission errors, HTTP permission loss, nested timeout, repeated outer and nested cursors, duplicate and null nodes, and moving counts. They invoke only `gh api graphql` reads. Aggregate acquisition is bounded to 8 MiB of responses, at most 100 rows per page, and explicit row/page limits. No live account call or review/thread/comment mutation was performed.

The full core validation output is preserved in `VALIDATE-15.log`. No GUI trial applies to this headless acquisition slice.
