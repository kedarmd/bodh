# Issue #36 — performance and support qualification

## Scope and status

This evidence separates measurements that exist from release claims still requiring qualification. The recorded native timings are from the bounded sequence-renderer diagnostic in `spikes/native-sequence`; they are not timings for a representative Bodh PR review. The capability experiment is against public `github.com` repositories only. The current native release environment was exercised by #35 and the Findings layout was visually accepted under #32. No X11, other distribution, Enterprise host, or long-duration resource test is claimed.

## Reproducible native measurement

The repository contains an opt-in repeatable profile runner: `./scripts/validate profile`. A fresh run was attempted at integration revision `e8989fe` in a clean source worktree except for this evidence file, but its cold release target was still compiling third-party dependencies after about four minutes. It was stopped before the profile executable launched to avoid duplicating the completed, controlled release comparison; the partial build transcript is preserved in [PROFILE-36-COLD-BUILD-STOPPED.log](PROFILE-36-COLD-BUILD-STOPPED.log). It contains no measurement results. It emits the revision, dirty state, OS, Rust/Cargo versions, Cargo target paths, then launches a locked release build and the hidden GPUI profile window. The test harness uses three deterministic workloads (7, 120 and 1,000 interactions), two warm-up draws and ten samples per operation. It reports nearest-rank p50/p95 for selection and inspector resize. The measurement covers state update, native layout, text/path paint and per-frame GPUI arena cleanup. It excludes physical input dispatch, GPU submission, compositor presentation and perceived latency. The `16.7 ms` result is a diagnostic comparison reference, not a product limit.

The controlled comparison was previously run at 1280×800 on the same host with locked dependencies and release optimization, without concurrent compilation. The baseline was commit `8de16ba` with the corrected profile module transplanted into a distinct temporary package identity; the fixed renderer implementation is commit `dbb3baa` (`Cull offscreen sequence elements and paths for #2`). This #36 task did not produce a new profile sample; the exact prior raw runs are used below. Raw output is preserved in [redraw-before-release.txt](../../spikes/native-sequence/evidence/redraw-before-release.txt) and [redraw-after-release.txt](../../spikes/native-sequence/evidence/redraw-after-release.txt). This confirms that viewport-bounded rendering changed 120- and 1,000-interaction CPU redraw from 10.238/93.785 ms selection p50 to 1.456/1.458 ms; resize p50 changed from 9.582/91.774 ms to 0.515/0.595 ms. The corrected run reached a maximum (p95, ten samples) of 2.856 ms selection and 1.585 ms resize for the ordinary flow, 2.279/0.576 ms for 120 interactions, and 2.110/0.821 ms for 1,000 interactions. Raw artifacts do not include hardware/version headers themselves; the contemporaneous host and method record is in [renderer evidence](../../spikes/native-sequence/EVIDENCE.md).

Actual native feedback was collected separately from those CPU numbers. After the renderer fix the user reported selection and resize felt smooth with no lag or crash, then confirmed the scrolling/partial-row/source-selection checklist. The original unexplained SIGKILL remains in the record; no crash-free guarantee is inferred. See the same renderer evidence for failed and successful trials, captures, and process memory observations.

This benchmark is a handcrafted diagram fixture, not a real PR. It does not measure time-to-useful-review, Git/gh acquisition, diff/source navigation on a large repository, large thread bodies, long discussions, Findings, or end-to-end resource growth. It is not suitable to extrapolate latency from 1,000 interactions to arbitrary PR size.

## Storage and retained material

Ticket #34 adds a public-service retention fixture: one complete discussion observation, three failed refreshes, and a later complete refresh. The test demonstrates per-preparation history bounded to the newest complete fallback plus the latest partial attempt, and to one complete observation after success. It verifies availability through the public load API. GitHub pagination/network calls stay outside the pruning transactions. See [migration and cache evidence](EVIDENCE-34.md).

This is an observation-count bound, not a byte bound. A discussion acquisition has an 8 MiB transport limit, and normalized page/thread rows duplicate some content. The #34 evidence does not measure database-file growth. Preparation/context eviction is not implemented: a complete reference index covering current results, source, unpublished drafts, compact prior concerns, and uncertain publication recovery does not exist. These payloads are preserved; total database size has no qualified upper bound. No forced Git-object eviction or full repeated prepare/import/follow-up/publication/restart resource test was run.

The optimized sequence diagnostic previously showed about 154 MiB current / 158 MiB peak service-cgroup memory in one point observation. This includes GPU/driver allocation and is not process RSS or an application-wide memory budget. The earlier flow-switch harness observed about 96 MiB process RSS. Neither observation measures long-duration cache growth or Bodh's full product workspace.

## Polling, inactivity, syntax, and packaging

The current native workspace checks freshness only while the workspace is active and a render occurs. A check becomes eligible after 60 seconds since the previous one, and the operation timeout is 12 seconds. There is no resident daemon or fixed background timer. Inactive-window CPU/network use and close/reopen behavior were not measured as a workload; the source gating is not presented as a measured inactivity guarantee.

Syntax highlighting is a small deterministic lexer, not a parser or grammar bundle. Its keyword tables cover Rust, JavaScript/TypeScript, and Python; it recognizes simple comments, strings, numbers and listed keywords. Unknown languages remain plain text. No other file-language coverage is promised. The installed identifiers are CLI `bodh`, native executable `bodh-gui`, GPUI app ID `bodh`, and desktop entry `Bodh`. The installed launcher and desktop entry were checked on the recorded Wayland host; desktop menu activation was not directly exercised.

## Qualification decision

The existing profile tool and fixture provide reproducible native CPU comparison for the sequence renderer, with real native interaction feedback. The evidence supports that bounded renderer's performance correction only. The remaining release envelope is not justified yet: there are no representative large real-review datasets, no end-to-end memory/cache measurements, no inactive-resource trial, no global byte/retention budget, and no Enterprise/X11/distro qualification. Keep those as explicit limitations; do not convert the diagnostic frame reference or observation-count cap into product limits.
